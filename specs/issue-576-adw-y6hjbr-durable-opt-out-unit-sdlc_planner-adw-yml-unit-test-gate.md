## Feature Description

Today the unit-test phase gate is read from `.adw/project.md` (`## Unit Tests: enabled`). That file is regenerated by `/adw_init` on every framework upgrade, so the operator's gate policy is silently clobbered on regen. This feature moves the **runtime** unit-test phase gate to the durable `.github/adw.yml` descriptor, which lives outside `.adw/` and is therefore never overwritten by regeneration (the same rationale that keeps `.adw-version` outside `.adw/`).

The existing `adws/core/adwYmlConfig.ts` deep module already parses `.github/adw.yml` for the framework-upgrade `hitl` auto-merge policy. This feature extends that one module with a second boolean key — `unitTests` — that **defaults to enabled (opt-out)**: when the file is absent, the key is omitted, or the value is malformed, unit tests run. Only an explicit `unitTests: false` disables the gate.

`/adw_init` is taught to create `.github/adw.yml` from a **self-documenting, fully-commented template** — but only when the file does not already exist, never overwriting an operator's edits. Because the keys in the template are commented out, a freshly-created file resolves to the defaults (gate enabled), while the inline documentation tells the operator exactly how to opt out without reading source.

Finally, the gate is read in the **normal workflow-init path** (`initializeWorkflow()`), not only during framework upgrade, and surfaced on `WorkflowConfig` so the unit-test phase consumes it directly.

This is the first slice of the parent PRD's staged rollout ("PR 1: unit-test layer"). It deliberately scopes to the gate move only; the JUnit structured-report contract, `testDirectory`, and the proof/screenshot overhaul are later PRs.

## User Story

As an ADW operator,
I want the unit-test gate to live in a durable `.github/adw.yml` that defaults to enabled and is created (but never overwritten) by `adw_init` with a self-documenting commented template,
So that my gate policy survives framework upgrades, silent-green is prevented by default, and I can configure the policy without reading framework source.

(Parent PRD user stories 16, 17, 18, 19.)

## Problem Statement

The unit-test phase gate is read from `.adw/project.md`, which `/adw_init` regenerates wholesale on every framework-hash upgrade. An operator who sets the gate in `project.md` loses that setting on the next upgrade — the policy is not durable. There is also no opt-out default story: the gate is currently opt-in via a `project.md` section, which means a misconfigured or regenerated repo can silently skip unit tests and report green on an unrun suite.

## Solution Statement

Extend the existing `adwYmlConfig` deep module with a `unitTests: boolean` key that defaults to `true` (enabled, opt-out), mirroring the established `hitl` parsing conventions (quoted/uppercase/inline-comment tolerance, malformed → default + warn). Add a unit-testable `writeAdwYmlTemplateIfAbsent(worktreePath)` helper plus an `ADW_YML_TEMPLATE` constant (a self-documenting, fully-commented template whose commented keys resolve to the defaults). Teach `/adw_init` to invoke a deterministic create-if-absent write of that template (never overwriting an existing file). Read `.github/adw.yml` in `initializeWorkflow()` and expose it on `WorkflowConfig`, and switch `unitTestPhase.ts` to read the gate from `config.adwYmlConfig.unitTests` instead of `project.md`.

The `.adw/project.md` `## Unit Tests` section and its `parseUnitTestsEnabled` parser are **retained** — they continue to drive *plan generation* (whether planners emit unit-test tasks). Only the *runtime phase gate* moves to `adw.yml`. This keeps the change narrowly scoped to the issue's acceptance criteria.

## Testing Strategy

### Unit Tests
`.adw/project.md` contains `## Unit Tests: enabled`, so unit tests are in scope. All new behaviour is in pure/deep functions with injectable I/O — tested through the public interface (inputs → outputs/verdicts), mirroring the existing `adwYmlConfig.test.ts` and `adwVersion.test.ts` patterns. No assertions on private helpers or call sequencing.

- **`parseAdwYml` (pure)** — table-style coverage of the new `unitTests` key: true/false, absent (default true), malformed (default true + warn), quoted, uppercase, inline comment, combined with `hitl` in both orders, first-occurrence-wins, and "malformed `hitl` does not block `unitTests`". Plus updated existing `hitl`-only assertions to the new two-field shape.
- **`readAdwYmlConfig` (filesystem wrapper)** — temp-dir fixtures: absent file → defaults (`unitTests: true`); `unitTests: false` file → disabled; `hitl`-only file → `unitTests` default.
- **`writeAdwYmlTemplateIfAbsent` (create-if-absent/non-overwrite)** — temp-dir fixtures: creates the file and `.github/` dir when absent (`{ created: true }`, parses to defaults); leaves an existing file byte-for-byte untouched (`{ created: false }`).
- **`ADW_YML_TEMPLATE` (drift guard)** — `parseAdwYml(ADW_YML_TEMPLATE)` resolves to the defaults, proving the shipped template documents without changing behaviour and stays in sync with the parser.
- **Regression guard for the consuming sites** — `adwUpgrade.test.ts` stubs/assertions updated to the new shape; `tsc` (root + `adws/tsconfig.json`) proves `unitTestPhase.ts` and `workflowInit.ts` consume `adwYmlConfig` with correct types. The phase rewiring itself is verified by type-checking + the build (no new phase-level test is required by the acceptance criteria, which scope unit tests to the parser + writer).

### Edge Cases
- `.github/adw.yml` absent → `unitTests: true` (gate enabled). Critical: ADW self-host has no `.github/adw.yml`, so the existing unit suite must keep running (no regression).
- `unitTests` key present but value malformed (`maybe`, `1`, empty) → default enabled + warn.
- `unitTests: false` with surrounding whitespace, quotes, mixed case, or a trailing inline comment → disabled.
- File contains `hitl` but not `unitTests` (and vice versa) → the missing key takes its default.
- Both keys present in either order → both honoured independently.
- Duplicate `unitTests` lines → first wins.
- `writeAdwYmlTemplateIfAbsent` when `.github/` exists but `adw.yml` does not → creates the file; when both exist → no overwrite.
- Operator's `.github/adw.yml` with custom content survives a regen pass (idempotent create-if-absent), even though editing `adw_init.md` raises the framework hash and triggers regeneration.

## Notes
- **Coding guidelines:** strict TypeScript, immutability (return new config objects; the template is a `const`), purity (`parseAdwYml`, `parseBooleanScalar`, `ADW_YML_TEMPLATE` are pure; I/O isolated in `readAdwYmlConfig`/`writeAdwYmlTemplateIfAbsent`), guard clauses and max-depth-2 nesting, file < 300 lines (`adwYmlConfig.ts` stays well under), and no dead code (drop the unused `parseUnitTestsEnabled` import from `unitTestPhase.ts`). No decorators. No new runtime dependency — the hand-rolled scalar parser is kept, consistent with `core/projectConfig.ts` and the existing `adwYmlConfig` module.
- **No new library required.** Per `.adw/commands.md` the install command is `bun add <package>`, but none is needed.
- **Scope boundary — two distinct unit-test signals.** This issue moves only the *runtime phase gate* to `adw.yml`. The `.adw/project.md` `## Unit Tests` section and `parseUnitTestsEnabled` are intentionally retained because they govern *plan generation* (see `app_docs/feature-jjxkk9-conditional-unit-tests-plan-template.md`). A future slice may unify plan generation onto `adw.yml`; that is out of scope here and not in the acceptance criteria.
- **Migration ripple (intended, per PRD).** Defaulting the gate to enabled means a target repo that previously had `## Unit Tests: disabled` in `project.md` and no `.github/adw.yml` will, after its next upgrade, see the gate read from `adw.yml` and default to enabled (unit tests run). To stay opted out, the operator sets `unitTests: false` in `adw.yml`. The PRD accepts this ripple; the later "hard-fail only when a framework is detected" rule (a subsequent PR) bounds the blast radius. ADW self-host has no `.github/adw.yml` and wants the gate enabled, so there is no self-host regression.
- **Emit-parse coupling (PRD "Further Notes").** Because `.github/adw.yml` is created by `/adw_init` and `adw_init.md` is a framework hash input (`hashInputs:` frontmatter), editing `adw_init.md` raises `.adw-version` and triggers `adwUpgrade` to regenerate `.adw/` across registered targets — the intended propagation that rolls the create-if-absent step out to every repo. The create-if-absent guarantee ensures regeneration never clobbers an operator's existing `adw.yml`.
