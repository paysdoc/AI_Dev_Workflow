## Chore Description
The daily docs-index sweep (`adws/triggers/docsIndexSweep.ts`) filed a `hitl` report. It says `.adw/conditional_docs.md` on `dev` fails the round-trip check (`serializeConditionalDocs(parseConditionalDocs(content)) !== content`), and the first divergence is at **line 15**.

This repeats issue **#973** exactly. That issue had the same fingerprint `1198802e28ef` and the same line 15. It was planned in `specs/issue-973-adw-tu043o-docs-index-health-1-sdlc_planner-fix-conditional-docs-serialization.md` and closed by PR #974, which added a regression test. The sweep re-filed the report one day later because the root cause was never addressed. **The cron runner still runs ADW code that predates `Decisions:` support. The index file itself is canonical.**

Evidence gathered during planning:
- Line 15 of `.adw/conditional_docs.md` is `  - Decisions:`. It is the first `Decisions:` header in the file: the first entry is `app_docs/feature-9gjajh-test-report-and-verdict.md`, and its `Decisions:` lists `0043`.
- `Decisions:` parse/serialize support arrived in commit `92a759ff` ("map module docs to ADRs in docs gate", 2026-10-01).
  - The parser before that commit (`git show 92a759ff^:adws/core/conditionalDocsRegistry.ts`) only knows the `owns` and `conditions` lists. It ignores `  - Decisions:` and keeps `activeList === 'conditions'`, so `    - 0043` is added to `conditions` and serialized at line 15.
  - That is exactly the reported divergence. The comment at the top of `adws/core/conditionalDocsRegistry.ts` describes this fallback.
- The cron runner runs a clone of `main`.
  - The main checkout's `HEAD` and `origin/main` are both `3d43b81a` ("Merge pull request #945 from paysdoc/dev"), which does **not** contain `92a759ff`.
  - `origin/main..origin/dev` is 150 commits.
  - `app_docs/feature-9gjajh-document-phase.md` already documents this under Gotchas: "The runner lags `dev` until the owner promotes it … files a `non-canonical` report until `dev` is promoted and the runner restarted."
- A static scan of the current file against the **current** parser rules found nothing non-canonical:
  - every line is the preamble header, `- <docPath>`, `  - Owns:|Conditions:|Decisions:`, `    - <item>`, or blank;
  - no doubled blank lines, and every entry is preceded by exactly one blank line;
  - every entry's blocks are in canonical order (`Owns → Conditions → Decisions`);
  - the file ends with exactly one trailing newline;
  - it has 43 `Decisions:` blocks.
- `.adw/conditional_docs.md` in this worktree is identical to `origin/dev` (`4c897275`).
- No sweep repair PR (branch `chore/docs-index-sweep`) has landed on `dev` since `92a759ff`. Every change to the index in that window came from document-agent commits or manual merges. So the stale serializer has not moved any decision numbers under `Conditions:`, and nothing needs reverting.
- The regression test that #974 asked for already exists: `adws/core/__tests__/docsIndexHealthDecisions.test.ts:21` ("an index whose first entry ends in a Decisions: block reports no non-canonical violation"). Adding another would duplicate it.

The chore has these parts:
1. Use the current code to confirm that the index round-trips and that the gate is clean. Make a formatting-only fix only if the gate unexpectedly reports a divergence.
2. Confirm that the existing regression test still covers the reported shape and passes. Do not add a duplicate.
3. Make **no** change to the parser, serializer, health module, gate, sweep, or the conditional doc. All of them are already correct, and the doc already describes the lag.
4. Escalate the operational fix to the human operator in the PR description: promote `dev` → `main` and restart the cron runner. After that, the next sweep finds a clean index and closes #979 automatically (`docsIndexSweep.ts`: "closed when the index goes clean"). Until then, every agent-side "fix" is a no-op, and the report keeps coming back.

The issue's "Resolution rule" line (the module doc keeps its package globs, and so on) is standard boilerplate for overlap violations from `docsIndexReportBody.ts`. It does not apply here: the only violation is `non-canonical`, and no `Owns:` glob is reassigned.
