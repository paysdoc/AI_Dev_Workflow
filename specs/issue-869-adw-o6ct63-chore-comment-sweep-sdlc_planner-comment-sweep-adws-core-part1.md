## Chore Description
First of sixteen comment de-bloat sweep batches from the PRD `specs/prd/comment-debloat.md`. It covers 33 files in `adws/core/` (23 source files, 10 unit-test files). Re-measured at planning time: **914 comment lines**. That includes 62 banner lines, 27 lines that cite an issue number, and 110 JSDoc blocks. None of the files has a shebang. The only `eslint-disable` directives are in `__tests__/phaseRunner.test.ts`.

The job is **comment-only**. Every edit either deletes comment text or trims it, plus the blank lines left behind. No token of code may change. That includes string and template literals: `#`-prefixed lines inside `ADW_YML_TEMPLATE` are string content, not comments. Imports, ordering and formatting of code lines also stay as they are. The comment-only guard (`adws/checkCommentOnly.ts`, shipped by #853) proves this mechanically. It compares each file's non-trivia TypeScript token stream against the default branch.

Deletion rules (PRD › *Implementation Decisions › Deletion rules per comment kind*, as narrowed by the issue):

1. **Banners**: delete every line of dashes or box-drawing characters (`// -----`, `// ── … ──`). Delete the label line that sits between two banner lines too (e.g. `// Parser`, `// §1 globsOverlap — overlap matrix`). With the banner gone, the label is just a section heading.
2. **Name-restating JSDoc**: delete any `/** … */` block, or `@param`/`@returns` tag, that only repeats what the identifier, its type signature or its parameter names already say.
3. **Next-line narration**: delete inline comments that describe the statement below them (`// Read existing state if present`, `// Should not throw`).
4. **Issue-number tags**: strip `#NNN`, `(#NNN)`, `(issue #NNN)` and `issue #NNN` wherever they appear in a comment. Keep what is left only if it still gives a reason, invariant or ordering constraint. Otherwise delete the whole comment.
5. **Mixed comments**: keep only the sentences that state an invariant, an ordering constraint, or the reason for a non-obvious choice. Drop narration, history ("moved from…", "replaces…", "per the parent PRD…", "Step 9 of the plan") and restatements. Do **not** rewrite the prose that survives. Trimming means deleting whole sentences, clauses or list items, plus whatever minimal punctuation fix the remaining fragment needs.
6. **Keep unchanged**: `eslint-disable` / `eslint-disable-next-line` directives, including the ones trailing a line in `phaseRunner.test.ts` at lines 196 and 210. Also keep any `@deprecated` tag, since it drives editor tooling.

Blank-line hygiene: when you delete a comment, don't leave two or more blank lines in a row where there was one before, and don't leave a blank line at the top of a file. Blank lines are trivia to the guard, so this is purely cosmetic.
