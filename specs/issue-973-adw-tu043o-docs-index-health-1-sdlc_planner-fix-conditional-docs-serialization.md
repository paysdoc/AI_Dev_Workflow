## Chore Description
The daily docs-index sweep (`adws/triggers/docsIndexSweep.ts`) filed a `hitl` report saying `.adw/conditional_docs.md` on `dev` fails the round-trip check (`serializeConditionalDocs(parseConditionalDocs(content)) !== content`), with the first divergence at **line 15**.

The research points to one cause: **the sweep ran on an ADW checkout that predates `Decisions:` support. The index file itself is canonical.**

Evidence gathered during planning:
- Line 15 of `.adw/conditional_docs.md` is `  - Decisions:`, the first `Decisions:` header in the file (first entry `app_docs/feature-9gjajh-test-report-and-verdict.md`, `Decisions:` → `0043`).
- The `Decisions:` block was added to the parser and serializer in commit `92a759ff` ("map module docs to ADRs in docs gate"), merged to `dev` by PR #948 on 2026-10-01 22:50 +0200. In the earlier parser (`git show 92a759ff^:adws/core/conditionalDocsRegistry.ts`), `  - Decisions:` hits the "unrecognized lines are ignored" branch. `activeList` stays `'conditions'`, so `    - 0043` is added to `conditions` and serialized back as a Conditions item. As a result, line 15 becomes `    - 0043` where the original has `  - Decisions:`. That is exactly the reported divergence. The code comment at the top of `conditionalDocsRegistry.ts` describes this fallback ("a parser that predates it reads the items as Conditions lines").
- A static scan of the current file against the **current** parser rules found no non-canonical construct:
  - every line is one of: the preamble header, `- <docPath>`, `  - Owns:|Conditions:|Decisions:`, `    - <item>`, or blank;
  - no trailing whitespace, tabs, or CR;
  - no doubled blank lines, and every entry is preceded by exactly one blank line;
  - every one of the 47 entries is in canonical block order (`Owns → Conditions → Decisions`, no empty headers);
  - no duplicate docPaths;
  - exactly one trailing newline.
- `.adw/conditional_docs.md` in this worktree matches `origin/dev`, and the last change to it (`736b80a9`, 12:26 +0200) predates the issue (13:46 +0200). So the sweep assessed the same content.

The chore therefore has three parts:
1. Confirm with the current code that the index round-trips. Make a minimal formatting-only fix only if the gate unexpectedly still reports a divergence.
2. Add a focused regression unit test. It pins that an index whose first entry has a `Decisions:` block (the shape at the head of the real index) is canonical and yields no `non-canonical` violation.
3. Do **not** change the parser, serializer, or the sweep. Once the cron host runs current `dev`, the sweep finds no violations and closes #973 itself (`docsIndexSweep.ts`: "closed when the index goes clean").

The issue's "Resolution rule" line (module doc keeps package globs, etc.) is the standard boilerplate for overlap violations. It does not apply to a non-canonical violation: no `Owns:` glob is reassigned.
