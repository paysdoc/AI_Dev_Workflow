# Specs and PRDs

## Overview

The `specs/` directory is the ADW framework's historical record of implementation plans and product requirement documents. Plan files capture what was intended before each build phase; PRD files in `specs/prd/` capture larger architectural decisions and cross-cutting module designs that span multiple issues.

## Responsibilities

- Store per-issue plan files generated by the planning agents, following the naming convention `issue-{issueNumber}-adw-{adwId}-sdlc_planner-{descriptive-name}.md`.
- Store PRD documents in `specs/prd/` for architectural features: current PRDs cover ADW init hash/label classification, the app-docs module living-docs system, BDD rewrite surface matrix and tiered regression, D1 cost database, supply-chain audit (depaudit), GitContext repo-context authority, multi-language test and BDD support, orchestrator coordination and resilience, scenario rot prevention and promotion, TDD/BDD integration, and test/review/refactor flow.
- Retain the `ADW_PYTHON_SUPPORT_RECOMMENDATION.md` architectural recommendation alongside the PRDs.
- Serve as the canonical reference for the scope and implementation decisions associated with each completed issue.

## Contracts & Invariants

- Plan files are write-once artifacts produced by the planning agent; they are not updated after the build phase begins.
- PRD files in `specs/prd/` reflect architectural intent at the time of writing; they may diverge from the current implementation as the codebase evolves — they are not kept in sync automatically.
- The plan file path is recorded in `AgentState.planFile` and used by the build agent to find its instructions.

## Configuration

No configuration. Plan files are created by the planning commands (`/feature`, `/bug`, `/chore`, `/pr_review`) and stored in `specs/` by convention.

## Gotchas

- The `specs/` directory accumulates plans from all past issues; it is not cleaned up automatically. Plans for abandoned or discarded issues remain indefinitely.
- Some issues have multiple plan files (e.g., `issue-114-plan.md` alongside `issue-114-adw-...-sdlc_planner-....md`) from replanning cycles; the `AgentState.planFile` pointer determines which one the build agent uses.
- PRD files in `specs/prd/` are read by agents during planning when referenced in `conditional_docs.md`; outdated PRDs can misdirect planning if not kept current.
