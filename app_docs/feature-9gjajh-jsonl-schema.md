# JSONL Schema

## Overview

The JSONL schema module is ADW's only contract with the Claude CLI's `--output-format stream-json` envelope — Anthropic has declined to publish a stable schema for it (claude-code#53516). It provides a live probe that reconciles `adws/jsonl/schema.json` against the pinned CLI, a conformance checker that validates fixture files against that schema and through ADW's parsers, and a fixture updater for keeping test fixtures current. `.github/workflows/envelope-conformance.yml` runs the checker (and, once a secret is configured, the live probe's read-only `--check` mode) on every pull request.

## Responsibilities

- Define typed schema structures in `types.ts`: `SchemaField`, `EnvelopeSchema` (`probedAt`, optional `cliVersion`, and a `type`/`type-subtype`-keyed map of field lists), `ConformanceResult` (per-fixture pass/fail with `lineCount`, missing/extra fields and parser/extractor errors), `UpdateResult`, and `LiveDriftReport`.
- `schemaFields.ts` — pure keying and field helpers shared by every other module: `schemaKeyFor` (`type/subtype` when `subtype` is a string, else bare `type`), `resolveSchemaFields` (exact key first, then the bare-`type` fallback), `extractFieldSchema` (all observed fields required, `OPAQUE_OBJECT_FIELDS` recorded as `object` without nested fields), `findMissingFields`/`findExtraFields` (presence-only, dot-path notation).
- `schemaMerge.ts` — pure probe helpers: `PROBE_OWNED_TYPES` (`system/init`, `assistant`, `result/success`), `extractObservedSchema` (parses live probe output into a schema-key → fields map), `mergeObservedSchema` (reconciles only probe-owned keys, preserving hand-set `required` flags), `findLiveDrift` (compares committed vs. observed for CI's `--check` leg).
- `schemaProbe.ts` — spawns the pinned CLI (`--print --verbose --output-format stream-json --max-turns 1 --model haiku 'say hello'`) in a throwaway temp cwd; `probeClaudeJsonlSchema` (refresh mode, writes `schema.json`) and `checkClaudeJsonlSchema` (read-only `--check` mode, returns a `LiveDriftReport`) are both thin shells over the live probe plus the pure helpers.
- `conformanceCheck.ts` — `checkConformance` validates every `.jsonl` fixture in `adws/jsonl/fixtures/` and `test/fixtures/jsonl/envelopes/` (both overridable): JSON parse, per-line schema resolution and field presence, one `parseJsonlOutput` pass over the whole fixture (multi-line fixtures are a single parser/extractor run, not one per line), and one `AnthropicTokenUsageExtractor` pass. `formatConformanceReport` renders results as text; the standalone entry point exits non-zero on any failure.
- `fixtureUpdater.ts` — `updateFixtureEnvelopes` adds fields the schema marks required but a fixture line is missing (recursing into nested objects), using a type default; it never deletes a field and never overwrites a value already present. Shares `DEFAULT_FIXTURE_DIRS`/`DEFAULT_SCHEMA_PATH` with the checker (exported from `conformanceCheck.ts`) so a failing report's `jsonl:update` hint covers every fixture the gate checked.

## Contracts & Invariants

- **Keying and lookup order.** A schema entry is keyed `type` or `type/subtype` when the envelope carries a string `subtype`. Lookup tries the exact `type/subtype` key first, then the bare `type` key as a fallback, else the message has no schema coverage (informational, never a failure). The bare `result` entry is the fallback for any `result` subtype that has no keyed entry of its own (e.g. `error_max_turns`) — a `result` line whose `subtype` is itself missing also resolves here and fails naming `subtype` as missing, because `subtype` is one of the bare entry's required fields.
- **Probe-owned vs. capture-owned entries.** Probe-owned entries (`system/init`, `assistant`, `result/success`) are what a one-turn `say hello` run deterministically produces; only `schemaProbe.ts` may rewrite them, and it does so by merging (see below), never by overwriting wholesale. Capture-owned entries (`rate_limit_event`, `system/api_retry`, `result/error_during_execution`) and the bare `result` fallback come from real CLI captures the probe cannot trigger (a genuine rate limit, a documented retry message) and are hand-curated; the probe never touches them, even if a live run happens to observe one (e.g. an `allowed` `rate_limit_event` on an OAuth session).
- **Merge rules.** Refreshing a probe-owned entry that already exists keeps every committed field still observed live (with its committed `required` flag and nested `fields` merged the same way), drops a committed field the live CLI no longer emits, and appends a field the live CLI added as `required: false`. A brand-new probe-owned entry has every observed field marked `required: true` (the probe has only one live example).
- **Presence, not value type, is enforced.** `findMissingFields`/`findExtraFields` only check whether a field is present (`field.name in data`); a `null` value counts as present (`api_error_status` is `null` on a healthy `result/success`, `parent_tool_use_id` is `null` on a main-conversation message). `required: true` marks a field ADW's parsers or extractor actually read; `required: false` documents an observed-but-unread field so an additive CLI change never fails the gate.
- **Opaque objects.** `modelUsage` and `rate_limit_info.unifiedWindows` are recorded as `type: "object"` without nested `fields` — their keys are data (model ids, rate-limit window names), not schema.
- `checkConformance` treats an unknown message type (no schema coverage at all) as a pass with an informational `extraFields` entry, never a failure.
- A fixture is one JSON object per line; a multi-line fixture is a whole session excerpt. The checker resolves each line against the schema independently but runs the parser and extractor exactly once per fixture, over every line joined with `\n` plus a trailing `\n` — `parseJsonlOutput` buffers back a final segment that lacks a trailing newline instead of parsing it, so the join+append is required, not cosmetic (this was the reason the gate was dead on all four of its original fixtures). Parser assertions are conditional on what the fixture actually contains: any `assistant` line bumps the expected `turnCount`; any `result` line (any subtype, or none) must set `lastResult`; a `rate_limit_event` whose `rate_limit_info.status` is `"rejected"` must set `rateLimitRejected`. A `system/api_retry` line is only asserted not to throw — matching its `error` enum to the parser's `overloadedErrorDetected` flag is the detection slice's job, not this gate's.
- The extractor check reads `getEstimatedUsage()`, not `getCurrentUsage()`: once a `result` line finalizes the extractor, `getCurrentUsage()` switches to that result's `modelUsage`, which is `{}` when the very first call in the fixture was rejected (the stub's rate-limited response, or a probe run during an active limit). `getEstimatedUsage()` keeps the per-turn estimate the `assistant` lines produced instead.

## Configuration

- `CLAUDE_CODE_PATH` environment variable (or `claude` on PATH) determines which CLI binary the probe spawns, resolved through `resolveClaudeCodePath()`.
- The probe spawns in a fresh temp directory (`getSafeSubprocessEnv()`'s allowed vars only) so the repo's own `.claude/settings.json` hooks, `CLAUDE.md` and project memory are never loaded into the probed turn.
- `bun run jsonl:probe` (refresh, writes `schema.json`) and `bun run jsonl:probe:check` (read-only, CI's live leg — exits non-zero only on an unobserved probe-owned type or a missing required field, never on an additive field) both require a working CLI session; `ANTHROPIC_API_KEY` is the CI secret that gates whether the live leg runs at all.
- Schema and fixtures paths default to sibling directories of the module files; every entry point accepts overrides for use from tests (a throwaway schema copy, a throwaway fixtures directory).

## Gotchas

- A probe run during an active rate limit produces only a rejected `rate_limit_event` and an error result — no `assistant` or `result/success` line. Refresh mode fails with a message naming the unobserved probe-owned types and telling the operator to wait for the reset; `--check` reports the same types under `unobservedTypes`. Neither writes anything in that case.
- `rate_limit_event` is documented by the Agent SDK as rate-limit information for claude.ai subscription users; an API-key probe in CI never observes it. That is exactly why it is capture-owned and hand-curated rather than probe-owned.
- The CLI reports an API error — including a rate limit — as `subtype: "success"` with `is_error: true`; the error surfaces in `api_error_status`/`terminal_reason`/`result`, not in a distinct error subtype. A genuinely different result shape, `error_during_execution`, carries `errors` and no `result` field at all.
- The current CLI rejects `--output-format stream-json` in `--print` mode without `--verbose`; the probe's args always include both.
- Running the conformance check requires `schema.json` to exist; it throws if the file is missing rather than falling back to a default schema. The same is true of the fixture updater.
