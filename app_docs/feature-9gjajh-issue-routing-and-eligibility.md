# Issue Routing and Eligibility

## Overview

This module determines whether an issue is eligible for ADW processing and routes it to the correct workflow. It covers dependency resolution (including automatic region-overlap detection between two open issues), concurrency gating, the `issues.opened` label-routing path, the auto-merge retry loop, the `## Cancel` directive handler, the 14-day per-issue scenario retention sweep, and resolving which orchestrator script a resumed adwId routes back to.

## Responsibilities

- `parseDependencies`: extracts issue numbers from a `## Dependencies`, `## Depends on`, or `## Blocked by` section in an issue body. Matches `#N` references and full GitHub issue URLs.
- `parseKeywordProximityDependencies`: extends `parseDependencies` by also scanning the entire body for `#N` references preceded within 80 characters by a dependency keyword (`blocked by`, `depends on`, `requires`, etc.).
- `extractDependencies`: the full extraction pipeline — cache check first, then keyword proximity, then LLM fallback when the proximity parser finds fewer references than the total `#N` count in the body.
- `findOpenDependencies(issueBody, tracker, logsDir?, statePath?, cwd?, issueNumber?)`: calls `extractDependencies` then checks each dependency's state via `tracker.getIssueState()` (`tracker: Pick<IssueTracker, 'getIssueState'>` — a bound port, no `repoInfo`); unknown states are treated as OPEN (fail-closed).
- **Pure region-overlap decision** (`adws/triggers/regionOverlap.ts`): `parseRelevantFilesSection` extracts and normalizes file paths from a `## Relevant Files` / `## Touched Files` section in an issue body; `pathsOverlap` computes pairwise shared paths between two path sets; `decideSerialization` deterministically decides whether a candidate issue should defer behind an overlapping sibling. No I/O — all functions are pure over their inputs.
- **Durable overlap registration** (`adws/triggers/regionOverlapSignals.ts`): `registerRegionOverlapBlocker(deferral, currentBody, tracker)` idempotently inserts an annotated `## Blocked by #N <!-- adw:region-overlap -->` line into the deferred issue's body (via `buildBlockedByBody`) and posts a one-time explanatory comment (`formatRegionOverlapComment`); `tracker` is `Pick<IssueTracker, 'updateIssueBody' | 'commentOnIssue'>` — a bound port, no repository parameter to get wrong. Enforcement and unblocking then ride the existing declared-dependency path unchanged: `findOpenDependencies` blocks the deferred issue every subsequent cycle, and `handleIssueClosedDependencyUnblock` (`adws/triggers/issueClosedUnblockRouter.ts`) re-spawns it the moment the blocker's PR merges.
- `checkIssueEligibility(issueNumber, issueBody, providers)`: combines `findOpenDependencies` and `isConcurrencyLimitReached` into a single `EligibilityResult`; `providers` is `Pick<BoundProviders, 'issueTracker' | 'codeHost'>` (`EligibilityProviders`) — no more `repoInfo`-based resolution internally. Dependencies are checked first.
- `decideIssueOpenedRoute`: pure function — maps an `AdwLabelReading` to one of `opt_out`, `conflict`, `classified`, or `infer`.
- `extractPayloadLabelNames`: defensively extracts label names from a raw webhook issue payload object.
- `routeIssueOpened(params, deps?)`: the DI-orchestrated `issues.opened` handler — `params.boundary: LaunchBoundary` is a required field; `deps` defaults to `buildDefaultIssueOpenedRouterDeps(params.boundary)`, which resolves `checkEligibility` to `checkIssueEligibility(n, body, boundary.providers)` and `classifyAndSpawn` to `classifyAndSpawnWorkflow(n, boundary, args, …)`. Calls `decideIssueOpenedRoute`, then `checkEligibility`, then `classifyAndSpawn` with the appropriate label routing.
- `mergeWithConflictResolution(prNumber, codeHost, headBranch, baseBranch, worktreePath, adwId, logsDir, specPath, gitContext)` (`autoMergeHandler`): retries merge up to `MAX_AUTO_MERGE_ATTEMPTS`; for each attempt, dry-run checks for conflicts, invokes the `/resolve_conflict` agent when conflicts are detected, pushes the branch, and calls `codeHost.mergePullRequest(prNumber)` (`codeHost: Pick<CodeHost, 'mergePullRequest'>`); stops early on non-conflict merge failures. `gitContext` is a required parameter (#821) — the caller's own `GitContext` (e.g. `adwMerge.tsx`'s launch boundary) is threaded through for every git op in the retry loop; the function no longer falls back to constructing one internally.
- `handleCancelDirective(issueNumber, comments, boundary, cwd?, processedSets?)` (`cancelHandler`): scorched-earth cancel — extracts all adwIds from comments, SIGTERMs then SIGKILLs orchestrator processes, removes worktrees via `boundary.gitContext.removeWorktreesForIssue(issueNumber)` (#822 retired the direct `gitContextForSync` construction this used to do — see `app_docs/feature-9gjajh-github-api.md`), deletes agent state directories, clears GitHub comments via `boundary.providers.issueTracker` (`clearIssueComments`), and removes the issue from cron dedup sets. `boundary: LaunchBoundary` is required (#821) — no more repoInfo-only call shape.
- `handleRetryDirective`'s `review_failed` path (`retryHandler.ts`): a `## Retry` comment on a `review_failed` issue transitions it to `phase_timeout` (re-arming `resumeAttempts: 0`), which the cron's takeover path picks up on its next cycle and routes via `resolveResumeSpawn` to the orchestrator that actually owns the adwId.
- `resolveResumeSpawn(state)` (`adws/core/resolveResumeSpawn.ts`): pure function mapping an adwId's persisted top-level state to `{ script, args }` — `script = state.orchestratorScript ?? 'adws/adwSdlc.tsx'`, `args = [String(state.issueNumber), state.adwId]`. Consumed by `trigger_cron.ts`'s takeover branch to route a resumed adwId to the orchestrator that actually owns it (PR-review or SDLC) instead of assuming SDLC.
- `runPerIssueScenarioSweep(deps)` (`perIssueScenarioSweep`): the 14-day per-issue scenario retention sweep. `PerIssueSweepDeps.boundary` is a **required** field — the `LaunchBoundary` the caller (the cron, via `runPerIssueScenarioSweepTick`) already resolved, covering both git ops (`boundary.gitContext`) and forge ops (`boundary.providers`) under one resolved identity; the sweep performs no repo-identity resolution of its own and constructs no additional `GitContext` or providers. Lists tracked `features/per-issue/feature-{N}.feature` files, resolves each issue's linked-merged-PR date via `defaultGetMergedAt(codeHost, issueNum)` — which calls `boundary.providers.codeHost.listMergedPullRequests(200)` and matches the canonical "Closes owner/repo#N" body marker (`bodyLinksIssue`) against a merged PR, returning `null` on no match or on throw — and batches a file plus its `step_definitions/feature-{N}.*` siblings for removal once `isScenarioStale` (a pure age-only predicate: `now - mergedAt >= RETENTION_DAYS * 86_400_000`, `RETENTION_DAYS = 14`) returns true — unless the file is promotion-exempt. Listing, staleness reads, and the removal all run against a dedicated `SweepBase` (`adws/triggers/perIssueSweepPersist.ts`) — a worktree synced to fresh `origin/<default>` off the injected boundary's own repo — never the cron host's own, possibly stale, base checkout, and never cwd; the base is lazily created at most once per call, only when a base-dependent default actually runs, via `prepareSweepBase(deps.boundary)`.
- Promotion-awareness gate: for each age-stale file only, reads its content (from the synced sweep worktree) and calls `parsePromotionTagState` / `isPromotionExempt` from `adws/core/promotionTagState.ts` — a file tagged `@promotion-suggested-<date>` is kept (skipped), while `@promotion-declined` or untagged files are swept normally. An unreadable stale file is also skipped rather than deleted with unknown promotion state.
- `prepareSweepBase(boundary)` / `persistRemovalViaPr` / `cleanupSweepBase` (`perIssueSweepPersist`): the sweep's persistence orchestration. `prepareSweepBase` takes the `LaunchBoundary` as its sole parameter (never re-derives via `getRepoInfo()`/`gitContextForRepo`) and creates a dedicated worktree off fresh `origin/<default>` — reading the default branch via `boundary.providers.codeHost.getDefaultBranch()` and creating the worktree via `boundary.gitContext.createWorktreeForNewBranch(SWEEP_BRANCH, defaultBranch)` (`SWEEP_BRANCH = 'chore/scenario-sweep'`) — returning `null` (logged) on any resolution failure so the sweep degrades to a no-op for that cycle. The returned `SweepBase` carries `ctx` (`GitContext`) and `codeHost` (`CodeHost`) plus derived helpers `findOpenSweepPr` (wraps `codeHost.findPullRequestByBranch`, returning the PR number only when its state is `OPEN`) and `openPr` (wraps `codeHost.createPullRequest({...}).number` — returns the new PR's number directly). `SweepBase` no longer carries a `repoInfo` field — it was unused once forge ops moved onto `codeHost`. `persistRemovalViaPr` commits the removal batch on the dedicated branch (`ctx.removeAndCommitPaths`), pushes it (`ctx.pushBranch`), opens a PR into the default branch via `base.openPr` (guarded by an existing-open-PR idempotency check via `base.findOpenSweepPr`), and immediately merges it via `base.mergePr` (which wraps `codeHost.mergePullRequest`) — mirrors `adwUpgrade`'s non-SDLC dedicated-branch → PR → immediate-merge pattern, never a direct commit/push onto the shared default branch. `cleanupSweepBase` best-effort deletes the remote sweep branch and local worktree after every run.
- `runPerIssueScenarioSweepTick(cycleCount, sweep = boundPerIssueSweep())` (`trigger_cron.ts`): the cron dispatch seam, mirroring `runPromotionSweepTick`. Off-cadence cycles (`cycleCount % PER_ISSUE_SCENARIO_SWEEP_INTERVAL_CYCLES !== 0`) no-op. On-cadence with a non-null bound thunk it awaits the sweep inside a try/catch that logs and swallows any throw. When `cronBoundary` is `null` (e.g. the module was imported rather than launched as the cron entry script) `boundPerIssueSweep()` resolves to `null` and the tick **skips the pass with a warning log** — it never falls back to a cwd-derived identity. Called unconditionally every tick from `checkAndTrigger`, immediately before `runPromotionSweepTick`.
- `runJanitorPass(deps, targetReposDir)` / `discoverTargetRepoWorktrees(deps, targetReposDir)` (`devServerJanitor.ts`): walks `{targetReposDir}/{owner}/{repo}/` (default `TARGET_REPOS_DIR`, which may be a general projects folder shared with non-ADW repos, not an ADW-only directory) and kills stale dev-server processes left behind in terminal-stage or old worktrees. A `{owner}/{repo}` directory is admitted as an ADW target repo only when it carries **both** a `.git` entry and the `.adw` marker directory written by `adw_init` — an unmarked repo is skipped entirely before any `GitContext` construction, token resolution, or `lsof` probing, and the skip is silent (not logged) since it is the expected, common case on a shared projects folder. The per-repo worktree listing (`deps.listWorktrees`, extracted into `discoverRepoWorktrees`) is wrapped in its own try/catch: a failure (GitHub App not installed, deleted repo, network error) logs `Janitor: skipping ${owner}/${repo} — worktree listing failed: …` at `warn` and skips just that repo, so the rest of the pass still runs (#812).

## Contracts & Invariants

- `parseDependencies` only returns issue numbers from the heading section; `parseKeywordProximityDependencies` is a superset.
- The in-memory dependency cache is keyed by `issueNumber:sha1(body)[:12]`; a body change invalidates the cache entry.
- `findOpenDependencies` is fail-closed: any error fetching a dependency's state causes that dependency to be treated as OPEN and block the issue.
- Pure / no I/O in `regionOverlap.ts`: it imports no side-effecting modules. All GitHub writes (issue body update, comment) live exclusively in `regionOverlapSignals.ts`.
- Deadlock-free overlap tie-break: within a cluster of mutually-overlapping issues, the lowest issue number (or the lowest in-flight member, if any are in-flight) is always the anchor that others defer behind — no two issues can each block the other.
- No false positives: a candidate with no path signal (no `## Relevant Files` or `## Touched Files` section) is never serialized.
- `registerRegionOverlapBlocker` is idempotent: it checks for the `<!-- adw:region-overlap -->` annotation before writing, so a second call for the same deferral is a no-op (no duplicate `## Blocked by` line, no duplicate comment). A write failure is caught and logged rather than thrown — the in-memory deferral already excluded the issue for the current cycle, and the next cycle retries.
- `checkIssueEligibility` returns `open_dependencies` before `concurrency_limit` — dependency checks gate concurrency checks, not the other way around.
- `decideIssueOpenedRoute` precedence: `opt_out` > `conflict` > `classified` > `infer`. Opt-out is unconditional.
- When `route.kind === 'conflict'`, `routeIssueOpened` posts a `MULTI_LABEL_REFUSAL_COMMENT` and returns `refused_multi_label` — no spawn occurs.
- When `route.kind === 'infer'`, `classifyAndSpawn` is called with `persistInferredLabel: true` so the LLM-inferred classification label is written back to the issue for cron label-recovery.
- `mergeWithConflictResolution` stops the retry loop immediately on a non-conflict merge error (e.g. permissions, already merged); it only retries on conflict-related errors.
- `handleCancelDirective` is synchronous (uses a spin-wait for SIGKILL timing) and returns `true` even when individual steps fail — all errors are logged and execution continues to subsequent steps.
- `resolveResumeSpawn` is pure and total: no I/O, no side effects; always returns a valid descriptor. It defaults to `'adws/adwSdlc.tsx'` when `orchestratorScript` is absent on the state — back-compat for every adwId created before PR-review began persisting `orchestratorScript` (see `app_docs/feature-9gjajh-pr-and-merge-phases.md`), and for SDLC adwIds, which persist that same script at their own init.
- Takeover routing correctness: `trigger_cron.ts`'s takeover branch reads the takeover adwId's top-level state and routes via `resolveResumeSpawn`; if that state is unexpectedly absent, it falls back to spawning SDLC directly rather than crashing.
- `resolveResumeSpawn`'s args are always `[String(issueNumber), adwId]`, passed before any target-repo flags at the spawn call site, to avoid positional collision.
- `isScenarioStale` stays pure and age-only; promotion-state exemption is a separate, orthogonal gate checked only after a file is already found age-stale, so fresh (non-stale) files never trigger the extra content read.
- Promotion-tag parsing considers only Gherkin *tag lines* (every whitespace-separated token starts with `@`) — a Feature description or step that merely mentions `@promotion-suggested-…` or `@promotion-declined` as prose is not matched, so it can't produce a false exemption.
- `@promotion-declined` is terminal and wins over a lingering `@promotion-suggested-<date>` if both markers are present on the same file (a malformed/partially-written file resumes the normal TTL rather than being exempt forever).
- A stale file whose content can't be read is skipped (not deleted) — this mirrors `getMergedAt` returning `null` (also "don't delete") and self-heals on the sweep's next cycle.
- The sweep never commits a removal to the cron host's own base checkout (`frameworkRepoRoot` is never `reset --hard`) and never pushes the default branch directly — both the lease-rejected-push and stranded-local-commit failure modes are structurally ruled out.
- Because the removal is committed only on the dedicated `chore/scenario-sweep` branch — never to the local base — a push/PR/merge failure never removes the files from the index `defaultListFeatures` re-lists from; the still-open PR (found by `findOpenSweepPr`) is the retry/idempotency signal across sweep cycles, not a re-committed local state.
- `persistRemovalViaPr` never throws: a push/PR/merge failure is logged at `error` (not swallowed at `warn`) and the function returns, leaving the PR open (if one was opened) for the next cycle or a human/CI to merge.
- The sweep worktree/branch is best-effort pre-cleaned at the start of `prepareSweepBase` (via `ctx.removeWorktree`) and torn down via `cleanupSweepBase` in a `finally` on every exit path of `runPerIssueScenarioSweep`, so a stale worktree from an interrupted prior cycle never blocks the next one.
- `boundary` is a **required, not optional** field on `PerIssueSweepDeps` — a cwd-derived default would silently resweep whatever repo the cron process happens to be checked out in (the framework repo, since `assertCwdIsRepoRoot()` pins cron cwd there) instead of the target repo the cron was launched against. `runPerIssueScenarioSweepTick` enforces skip-not-fallback: a `null` launch boundary skips the pass rather than supplying one.
- A `{owner}/{repo}` directory under `TARGET_REPOS_DIR` is an ADW target repo for the janitor only when it carries both `.git` and `.adw`; a failure listing one repo's worktrees never aborts the pass (#812).

## Configuration

`MAX_AUTO_MERGE_ATTEMPTS` is a core constant. The LLM fallback in `extractDependencies` calls `runDependencyExtractionAgent` which uses the standard agent infrastructure (logs dir, state path). `DEPENDENCY_KEYWORDS` is a module-level constant array. The `routeIssueOpened` DI deps default to production implementations via `buildDefaultIssueOpenedRouterDeps`. Region-overlap detection is driven entirely by `## Touched Files` or `## Relevant Files` sections in issue bodies (bullet lists or inline backtick paths) — there is no separate config flag to enable or disable it. `resolveResumeSpawn` has no configuration of its own — it reads `state.orchestratorScript` (persisted by each orchestrator at init/completion) and falls back to `'adws/adwSdlc.tsx'` when absent. `RETENTION_DAYS = 14` gates the per-issue scenario sweep. `SWEEP_BRANCH = 'chore/scenario-sweep'` (`perIssueSweepPersist.ts`) is the stable dedicated branch the sweep removal is pushed to and PR'd from; `SWEEP_COMMIT_MESSAGE = 'chore: sweep stale per-issue scenarios (>14d post-merge)'` is unchanged from the pre-#758 direct-commit message.

## Gotchas

- The LLM fallback in `extractDependencies` is triggered only when `totalRefs > 0 && proximityDeps.length < totalRefs` — it is not called when the body has no `#N` references at all, or when the proximity parser found as many as there are total references.
- `syncWorktreeToOriginHead` in `mergeWithConflictResolution` pulls `origin/<headBranch>` into the worktree before the conflict check so the local and remote views are in sync; failures are logged as warnings and the loop proceeds.
- `checkMergeConflicts` does a real `git merge --no-commit --no-ff` and then calls `git merge --abort`; if the abort itself fails (already clean), the exception is swallowed.
- `handleCancelDirective` uses a synchronous spin-wait (busy loop for 500 ms) between SIGTERM and SIGKILL — this is intentional because cancel is a rare manual operation and the context does not support async waits.
- `resolveConflictsViaAgent` starts the actual merge (with conflict markers) before invoking the agent; if the merge happens to succeed cleanly (no conflict), the function returns true immediately without calling the agent.
- The `MULTI_LABEL_REFUSAL_COMMENT` references the CRON recovery layer as the mechanism that picks up the issue after label cleanup — this relies on `evaluateLabelRecovery` in the cron filter.
- The region-overlap pass only runs over issues already deemed spawn-eligible in the current cron cycle — an issue that is `paused`, `awaiting_merge`, or already `active` only contributes its `inFlight` signal when it appears in that same cycle's eligible set.
- The inserted region-overlap annotation line is `#N <!-- adw:region-overlap -->`, placed immediately after the first `## Blocked by` / `## Dependencies` / `## Depends on` heading (a new `## Blocked by` section is appended if none exists). Placement matters because `parseDependencies` is first-heading-wins.
- No LLM fallback for region-overlap: detection only uses the deterministic `## Relevant Files`/`## Touched Files` body-section parse. An issue with neither section is never serialized — safe (no false positives) but a possible missed detection.
- `resolveResumeSpawn`'s SDLC default means a `review_failed` state that predates `orchestratorScript` being persisted resumes as SDLC even if it was actually a PR-review run — the risk is bounded, since `orchestratorScript` has been stamped by both orchestrators since this resolver shipped.
- The promotion-tag parser/serializer (`parsePromotionTagState`, `serializePromotionTagState`, `isPromotionExempt`) lives in `adws/core/promotionTagState.ts` as a dependency-free pure module (no fs/git/gh imports) so it is unit-testable in isolation from the sweep's I/O; only `parsePromotionTagState`/`isPromotionExempt` are wired into the sweep today — `serializePromotionTagState` is built and unit-tested for a later automated promotion-sweep slice that will write the marker, and is not yet called from any production writer.
- `DEFAULT_DEPS.listWorktrees` (`devServerJanitor.ts`) constructs a `GitContext`, whose constructor probes the token provider; with the GitHub App configured that throws `HTTP 404` for any repo the App is not installed on — by design (#791/#792). Isolate it in the caller; never soften the resolver.
