# Issue Routing and Eligibility

## Overview

This module determines whether an issue is eligible for ADW processing and routes it to the correct workflow. It covers dependency resolution (including automatic region-overlap detection between two open issues), concurrency gating, the `issues.opened` label-routing path, the auto-merge retry loop, the `## Cancel` directive handler, the 14-day per-issue scenario retention sweep (with its unused step definition report — readers for cucumber-js, cucumber-jvm and playwright-bdd — and removal chore), and resolving which orchestrator script a resumed adwId routes back to.

## Responsibilities

- `parseDependencies`: extracts issue numbers from a `## Dependencies`, `## Depends on`, or `## Blocked by` section in an issue body. Matches `#N` references and full GitHub issue URLs.
- `parseKeywordProximityDependencies`: extends `parseDependencies` by also scanning the entire body for `#N` references preceded within 80 characters by a dependency keyword (`blocked by`, `depends on`, `requires`, etc.).
- `extractDependencies`: the full extraction pipeline — cache check first, then keyword proximity, then LLM fallback when the proximity parser finds fewer references than the total `#N` count in the body.
- `findOpenDependencies(issueBody, tracker, logsDir?, statePath?, cwd?, issueNumber?)`: calls `extractDependencies` then checks each dependency's state via `tracker.getIssueState()` (`tracker: Pick<IssueTracker, 'getIssueState'>` — a bound port, no `repoInfo`); unknown states are treated as OPEN (fail-closed).
- **Pure region-overlap decision** (`adws/triggers/regionOverlap.ts`): `parseRelevantFilesSection` extracts and normalizes file paths from a `## Relevant Files` / `## Touched Files` section in an issue body; `pathsOverlap` computes pairwise shared paths between two path sets; `decideSerialization` deterministically decides whether a candidate issue should defer behind an overlapping sibling. No I/O — all functions are pure over their inputs.
- **Durable overlap registration** (`adws/triggers/regionOverlapSignals.ts`): `registerRegionOverlapBlocker(deferral, currentBody, tracker)` idempotently inserts an annotated `## Blocked by #N <!-- adw:region-overlap -->` line into the deferred issue's body (via `buildBlockedByBody`) and posts a one-time explanatory comment (`formatRegionOverlapComment`); `tracker` is `Pick<IssueTracker, 'updateIssueBody' | 'commentOnIssue'>` — a bound port, no repository parameter to get wrong. Enforcement and unblocking then ride the existing declared-dependency path unchanged: `findOpenDependencies` blocks the deferred issue every subsequent cycle, and `handleIssueClosedDependencyUnblock` (`adws/triggers/issueClosedUnblockRouter.ts`) re-spawns it the moment the blocker's PR merges.
- `checkIssueEligibility(issueNumber, issueBody, providers)`: combines `findOpenDependencies` and `isConcurrencyLimitReached` into a single `EligibilityResult`; `providers` is `Pick<BoundProviders, 'issueTracker' | 'codeHost'>` (`EligibilityProviders`) — no more `repoInfo`-based resolution internally. Dependencies are checked first.
- `decideIssueOpenedRoute`: pure function — maps an `AdwLabelReading` to one of `opt_out`, `conflict`, `classified`, or `infer`.
- `extractPayloadLabelNames`: defensively extracts label names from a raw webhook issue payload object.
- `routeIssueOpened(params, deps?)`: the DI-orchestrated `issues.opened` handler — `params.boundary: LaunchBoundary` is a required field; `deps` defaults to `buildDefaultIssueOpenedRouterDeps(params.boundary)`, which resolves `checkEligibility` to `checkIssueEligibility(n, body, boundary.providers)` and `classifyAndSpawn` to `classifyAndSpawnWorkflow(n, boundary, args, …)`. Calls `decideIssueOpenedRoute`, then `checkEligibility`, then `classifyAndSpawn` with the appropriate label routing.
- `mergeWithConflictResolution(prNumber, codeHost, headBranch, baseBranch, worktreePath, adwId, logsDir, specPath, gitContext, rerunScenarios, wait = sleep)` (`autoMergeHandler`): retries up to `MAX_AUTO_MERGE_ATTEMPTS`; each attempt runs the local merge check (`checkLocalMerge`: fetch `origin/<base>`, dry-run merge, always abort → `LocalMergeCheck` = `clean` | `conflicts` | `unavailable`), then brings the base in through `bringBaseIn` (below), pushes the branch, re-runs the scenarios when base commits came in that no run has seen yet, and only then calls `codeHost.mergePullRequest(prNumber)` through `mergeWithStaleRetry`. A refused merge whose local check is `clean` and whose branch lacks base commits returns the `base_moved` step (back to the loop, which integrates and re-tests again); any other refused merge whose check is not `conflicts` is treated as stale mergeability (GitHub recomputes it in the background after a push, whatever the error text says) and re-asked after `STALE_MERGE_RETRY_DELAYS_MS` = 3s/6s/12s/24s via the injectable `wait`; a `conflicts` check ends the merge step and the outer attempt loop retries. It returns a `MergeOutcome` `{ success, error?, mergeAttempts, conflictResolutionRan, localMergeCheck, postMergeRed? }` — `mergeAttempts` counts every `mergePullRequest` call. `gitContext` and `rerunScenarios` are required: the caller's own `GitContext` is threaded through every git op, and no call site can skip the proof by omission.
- **Post-merge re-run** (`adws/triggers/baseIntegration.ts`, `adws/core/postMergeVerdict.ts`, `adws/phases/postMergeScenarioRerun.ts`): `bringBaseIn` reads `HEAD`, merges `origin/<base>` (clean `git merge --no-edit`, or `/resolve_conflict` via `resolveConflictsViaAgent`, which records the conflicted paths first) and reads `HEAD` again — `current` (HEAD did not move), `brought_in` (merged-in commits as `git log --oneline` lists them, conflicted files each once) or `unresolved`. `baseMovedPast` fetches and asks whether the base holds commits `HEAD` lacks. `rerunScenariosOnMergedBranch` reads `.adw/` from the merged worktree (no scenarios → green, no side effects), installs `commands.installDeps` and the runner's install command, allocates a port and runs `executeScenarioTestPhase` with state under `agents/<adwId>/merge-orchestrator`; `postMergeVerdict` turns the result into `green` or `red` with one `PostMergeFailure { title, detail }` per failed case/tag/dev server. It never throws: any error is a red verdict. A red verdict returns a `MergeOutcome` carrying `postMergeRed` with no merge call; `adwMerge.tsx` then records the park `human_gated` / `post_merge_bdd_red` (`recordPark`, `postMergeRedComment.ts`), merges nothing and exits 0. Green merges only while the branch still holds the base tip; a base that moved during the run is brought in and tested again.
- `isIssueLockHeldByLiveProcess(repo, issueNumber, ownPid)` (`spawnGate.ts`): true when the per-issue spawn lock has a live holder other than the caller. The dev-server janitor leaves such a worktree alone and the device janitor keeps such a workflow's devices, so a long `adwMerge` re-run at `awaiting_merge` is not swept.
- `buildMergeBlockedComment` / `buildMergeFailureCause(prNumber, baseBranch, outcome)` (`adws/forge/mergeBlockedComment.ts`): build the `## ADW Merge Blocked` comment `adwMerge.tsx` posts on `merge_failed`; the cause lists merge attempts, whether conflict resolution ran, the local merge check result, and the last error (capped at 500 chars). `adwMerge.tsx` also calls `startMergeLog(adwId)` so every `log()` line of the run is appended to `merge.log` in the adw logs dir (`setLogFile`/`resetLogFile` in `adws/core/logger.ts`; synchronous append, write failures swallowed).
- `handleCancelDirective(issueNumber, comments, boundary, cwd?, processedSets?)` (`cancelHandler`): scorched-earth cancel — extracts all adwIds from comments, SIGTERMs then SIGKILLs orchestrator processes, removes worktrees via `boundary.gitContext.removeWorktreesForIssue(issueNumber)` (#822 retired the direct `gitContextForSync` construction this used to do — see `app_docs/feature-9gjajh-github-api.md`), deletes agent state directories, clears GitHub comments via `boundary.providers.issueTracker` (`clearIssueComments`), and removes the issue from cron dedup sets. `boundary: LaunchBoundary` is required (#821) — no more repoInfo-only call shape.
- `handleRetryDirective`'s `review_failed` path (`retryHandler.ts`): a `## Retry` comment on a `review_failed` issue transitions it to `phase_timeout` (re-arming `resumeAttempts: 0`), which the cron's takeover path picks up on its next cycle and routes via `resolveResumeSpawn` to the orchestrator that actually owns the adwId. The handler's `paused` path calls `resolveResumeSpawn` directly instead of waiting for a takeover cycle: `## Retry` on a `paused` issue drops any pause-queue entry for the adwId and respawns immediately, passing the caller's own `--target-repo` args. Both call sites build the handler's required third parameter via `buildRetryHandlerDeps(boundary, targetRepoArgs)` — `trigger_cron.ts` hoists its `targetRepoArgs` above the directive loop, `trigger_webhook.ts` passes its per-event `webhookTargetRepoArgs`.
- `resolveResumeSpawn(state)` (`adws/core/resolveResumeSpawn.ts`): pure function mapping an adwId's persisted top-level state to `{ script, args }` — `script = state.orchestratorScript ?? 'adws/adwSdlc.tsx'`, `args = [String(state.issueNumber), state.adwId]`. Consumed by `trigger_cron.ts`'s takeover branch to route a resumed adwId to the orchestrator that actually owns it (PR-review or SDLC) instead of assuming SDLC.
- `runPerIssueScenarioSweep(deps)` (`perIssueScenarioSweep`): the 14-day per-issue scenario retention sweep. `PerIssueSweepDeps.boundary` is a **required** field — the `LaunchBoundary` the caller (the cron, via `runPerIssueScenarioSweepTick`) already resolved, covering both git ops (`boundary.gitContext`) and forge ops (`boundary.providers`) under one resolved identity; the sweep performs no repo-identity resolution of its own and constructs no additional `GitContext` or providers. One pass:
  1. **Directories** (`readDirectories`): reads `.adw/scenarios.md` from the sweep worktree and resolves them with `resolveScenarioDirectories` — never fixed paths.
  2. **Listing**: tracked `feature-{N}.feature` files under the per-issue directory (never under the regression directory); for each, resolves the linked-merged-PR date via `defaultGetMergedAt(codeHost, issueNum)` — `boundary.providers.codeHost.listMergedPullRequests(200)` matched on the canonical "Closes owner/repo#N" body marker (`bodyLinksIssue`), `null` on no match or throw — and batches the file plus its issue-named step files (`feature-N.*`, `feature-N-*`) from **every** step-definition directory once `isScenarioStale` (pure, age-only: `now - mergedAt >= RETENTION_DAYS * 86_400_000`, `RETENTION_DAYS = 14`) is true. Issue-named step files whose feature file is already gone (orphans) join the batch. Step-file listing excludes `.feature` files and anything under the regression directory. No feature-file content is read: no tag exempts a file.
  3. **Usage report** (`readStepUsage`, once per sweep): the runner's dry run in the sweep worktree, **before** the persist step, while that tree still equals the default branch (see `perIssueSweepStepUsage.ts` below). Outcome is `usage` (cucumber-js usage report), `unused` (cucumber-jvm / playwright-bdd unused-steps report), `not_supported` (logged `finding unused step definitions is not supported for BDD framework "<framework>" — skipped`) or `unavailable` (logged at `warn`).
  4. **Step-file protection** (`withoutUsedStepFiles`): with a usage report, a candidate step file holding a definition used by a feature file not being removed (or a definition whose pattern is shared) is kept and logged; with an unused-steps report or none, step files outside the per-issue directory are kept, since nothing can clear them (an unused-steps report cannot say which feature files use a definition) — step files inside it are removed by name.
  5. **Persist**: the batch goes through the unchanged `sweepRemovalGate` (`verifyRemoval` with `worktreeGateDeps`; `base_red` skips the cycle, `hard_fail` discards the batch) and `persistRemovalViaPr`; the function returns the paths that landed.
  6. **Removal chore** (only with a `usage` or `unused` outcome): `reconcileUnusedStepDefinitions` computes `unusedStepDefinitions(usages, landed)` or `remainingUnusedStepDefinitions(unused, landed)`, restricted to the step-definition directories and files at most one `adw:chore` issue (see below).

  Listing, staleness reads, the dry run and the removal all run against a dedicated `SweepBase` (`adws/triggers/perIssueSweepPersist.ts`) — a worktree synced to fresh `origin/<default>` off the injected boundary's own repo — never the cron host's own, possibly stale, base checkout, and never cwd; the base is lazily created at most once per call, only when a base-dependent default actually runs, via `prepareSweepBase(deps.boundary)`. Every collaborator (`listFeatures`, `getMergedAt`, `listStepDefSiblings`, `listOrphanStepDefs`, `gateRemoval`, `persistRemoval`, `readDirectories`, `readStepUsage`, `listOpenRemovalIssues`, `fileRemovalIssue`, `log`) is injectable; a fully-injected caller never creates a worktree.
- **Scenario directories** (`adws/core/scenarioDirectories.ts`, pure): `resolveScenarioDirectories(scenarios)` → `ScenarioDirectories { perIssue, regression, stepDefinitions }` — `## Per-Issue Scenario Directory` (default `features/per-issue`), `## Regression Scenario Directory` (default `features/regression`), and the step-definition directories: the configured `## Step Def Directory` then `<perIssue>/step_definitions`, each listed once. `normalizeRepoDirectory` yields repository-relative `/`-separated paths without a trailing slash, and `''` for empty, root, absolute or repository-escaping values (which fall back to the default). `isWithinDirectory(file, dir)` is true for the directory and paths under it, never for a prefix-sharing sibling or `''`.
- **Unused step report** (`adws/core/unusedStepReport.ts`, pure): one `StepUsageReader { framework, sourceExtensions, dryRunCommand, read }` per `## BDD Framework`. `resolveStepUsageReader(bddFramework)` (trimmed, case-insensitive) returns `{ kind: 'supported', reader }` for `cucumber-js`, `cucumber-jvm` and `playwright-bdd`; every other value — `behave`, empty, unknown — is `{ kind: 'not_supported', framework }`. `read(report, sources?)` returns one of two report shapes, or `{ kind: 'unreadable', detail }`:
  - **cucumber-js — usage report** (`{ kind: 'read', usages }`): `dryRunCommand` replaces the `--tags`/`-t` argument holding `{tag}` (space or `=`, double/single-quoted or bare, possibly a tag expression) with `--dry-run --format usage-json:{report}` (`REPORT_PATH_PLACEHOLDER`), keeping the repository's loaders, environment and package runner. `read` parses the `usage-json` array into `StepDefinitionUsage { file, line, pattern, usedBy }` (repository-relative, no leading `./`, `usedBy` de-duplicated and sorted, regular expressions shown as `/…/`).
  - **cucumber-jvm — unused-steps report** (`{ kind: 'read_unused', unused }`): `dryRunCommand` replaces `-Dcucumber.filter.tags=<…{tag}…>` with `-Dcucumber.execution.dry-run=true -Dcucumber.plugin=unused:{report}`, keeping every other argument (including `--rerun`); `null` when the command already sets either property. `read` parses the plain-text `unused` plugin report with `parseCucumberJvmUnusedReport` and places each method reference with `locateJvmStepDefinition` in the `.kt`/`.java` sources (`sourceExtensions`) the sweep hands it.
  - **playwright-bdd — unused-steps report** (`{ kind: 'read_unused', unused }`): only for ADW's own Playwright run-by-tag command (`ADW_PLAYWRIGHT_INSTALL_COMMAND && … npx playwright test … {tag}`), which becomes `cd features && (test -d node_modules || npm ci) && npx bddgen export --unused-steps > {report}`; `null` otherwise. `read` parses the output with `parsePlaywrightBddUnusedReport` and rebases each location onto `ADW_PLAYWRIGHT_PROJECT_DIR` (`features`).
  - Queries: `unusedStepDefinitions(usages, removed)` — definitions no feature file uses once `removed` is gone, sorted by file then line; `remainingUnusedStepDefinitions(unused, removed)` — the reported unused definitions less those in a `removed` file and those sharing a pattern (reuses `unusedStepDefinitions` with empty `usedBy`); `stepFilesStillUsed(usages, candidates, removedFeatures)` — candidate step files that hold a definition a surviving feature file uses.
- **cucumber-jvm report parser** (`adws/core/cucumberJvmUnusedReport.ts`, pure): `parseCucumberJvmUnusedReport(report)` strips ANSI colour, requires the `<n> unused step definition(s)` line first, skips an optional `Location  Expression` header, parses each row as `<location>  # <expression>`, and is `unreadable` when a row has no `# ` or the row count differs from `<n>`. `locateJvmStepDefinition(location, sources)` parses `<binary class>.<method>(<parameter types>)` (nested `Outer$Inner` resolves to `Outer`; Kotlin backtick names may hold spaces), picks the single source whose `package` and top-level type declaration match, and returns the line of that file's single declaration of the method (Kotlin `fun name(` / ``fun `name`(``, or Java `<type> name(`, comment lines ignored); otherwise `null`, and the reader puts the definition at `UNKNOWN_STEP_LOCATION` (`unknown`), line 0.
- **playwright-bdd report parser** (`adws/core/playwrightBddUnusedReport.ts`, pure): `parsePlaywrightBddUnusedReport(output)` strips colour, finds the `Unused steps (<n>):` line (anything before it, such as `Using config: …`, is ignored), drops the box-drawing borders and the `Pattern / Text │ Location` header, splits each `│ <text> │ <file>:<line> │` row on its last separator, drops a leading `Given `/`When `/`Then ` from the text, and is `unreadable` for empty output, no count line, a malformed row or a count mismatch. Files are returned as printed, relative to where the export ran.
- **Step-definition sources** (`adws/core/stepDefinitionSources.ts`): `readStepDefinitionSources(rootPath, directories, extensions)` walks each directory (missing ones and unreadable entries skipped, symlinks not followed) and returns `StepDefinitionSource { file, text }` for each file with one of the extensions, repository-relative, `/`-separated, de-duplicated and sorted; `[]` when `extensions` is empty.
- **Removal chore spec** (`adws/core/unusedStepIssueBody.ts`, pure): `buildUnusedStepIssue({ definitions, framework, defaultBranch })` → `{ title, body, labels: ['adw:chore'] }`. The body starts with the marker line `Reconciles: unused-step-definitions` (`UNUSED_STEP_ISSUE_MARKER`), lists each definition as `` `file:line` — `pattern` `` (at most `MAX_LISTED_UNUSED_DEFINITIONS = 100`, patterns truncated at `MAX_LISTED_PATTERN_LENGTH = 160`, a "… and N more" line for the rest), tells the pipeline to remove the definitions plus the helpers, fixtures and imports only they used, to leave every other definition and feature file alone, and to keep the checks green, and ends with a `## Touched Files` section so region-overlap serialisation applies. `findOpenUnusedStepIssue(issues)` returns the lowest-numbered open issue carrying the marker on a line of its own.
- **Usage I/O edge** (`adws/triggers/perIssueSweepStepUsage.ts`): `runStepUsageReport({ worktreePath, commands, reader, stepDefinitionDirectories?, readSources?, runProcess?, fileExists? })` runs `## Install Dependencies` when configured, runs the derived dry run in the worktree with `{report}` replaced by a shell-quoted path in a fresh `adw-step-usage-*` temp directory (always removed), reads the step-definition sources only when the reader has `sourceExtensions`, parses the report, and returns `usage` for a usage report, `unused` for an unused-steps report, or `unavailable` when no report was written, it is unreadable, or it names files the worktree does not hold (definitions at `unknown` excepted). When the report is unreadable and the dry run exited non-zero, the detail also names the command, its exit code and the tail of its output. `defaultReadStepUsage(getBase, logger)` loads `.adw/` from the sweep worktree, picks the reader, and passes `resolveScenarioDirectories(...).stepDefinitions` as the source directories. `reconcileUnusedStepIssue(unused, deps)` files nothing for an empty list, nothing while an open marker issue exists, and nothing when listing open issues throws (fail-closed); a failed `createIssue` is logged at `error` and retried next sweep. `defaultListOpenRemovalIssues(issueTracker)` searches open issues for `"unused-step-definitions"` (limit 100); `defaultFileRemovalIssue(issueTracker)` calls `createIssue` then `applyLabel` per label. `readStepUsageOutcome` never throws and does the not-supported / unavailable logging.
- `prepareSweepBase(boundary)` / `persistRemovalViaPr` / `cleanupSweepBase` (`perIssueSweepPersist`): the sweep's persistence orchestration. `prepareSweepBase` takes the `LaunchBoundary` as its first parameter (never re-derives via `getRepoInfo()`/`gitContextForRepo`) and creates a dedicated worktree off fresh `origin/<default>` — reading the default branch via `boundary.providers.codeHost.getDefaultBranch()` and creating the worktree via `boundary.gitContext.createWorktreeForNewBranch(SWEEP_BRANCH, defaultBranch)` (`SWEEP_BRANCH = 'chore/scenario-sweep'`) — returning `null` (logged) on any resolution failure so the sweep degrades to a no-op for that cycle. The returned `SweepBase` carries `ctx` (`GitContext`) and `codeHost` (`CodeHost`) plus derived helpers `findOpenSweepPr` (wraps `codeHost.findPullRequestByBranch`, returning the PR number only when its state is `OPEN`) and `openPr` (wraps `codeHost.createPullRequest({...}).number` — returns the new PR's number directly). `SweepBase` no longer carries a `repoInfo` field — it was unused once forge ops moved onto `codeHost`. `persistRemovalViaPr` commits the removal batch on the dedicated branch (`ctx.removeAndCommitPaths`), pushes it (`ctx.pushBranch`), opens a PR into the default branch via `base.openPr` (guarded by an existing-open-PR idempotency check via `base.findOpenSweepPr`), and immediately merges it via `base.mergePr` (which wraps `codeHost.mergePullRequest`) — mirrors `adwUpgrade`'s non-SDLC dedicated-branch → PR → immediate-merge pattern, never a direct commit/push onto the shared default branch. `persistRemovalViaPr` is a thin wrapper over the generalised `persistCommitViaPr(commit, base, label)`, which takes the commit step as a callback (returning whether anything was staged) and resolves `true` only when the sweep PR merged — `false` for an already-open sweep PR, nothing staged, or a failed push, PR creation or merge; it never throws — so a caller that must not act before its change lands can gate on the result. `SweepPersistSpec` (`{ branch, prTitle, prBody }`, passed as `prepareSweepBase`'s optional second parameter and defaulting to the per-issue sweep's) has two consumers, each with its own dedicated branch and PR copy: the per-issue sweep (`PER_ISSUE_SWEEP_SPEC`, `chore/scenario-sweep`) and the docs-index sweep (`DOCS_INDEX_SWEEP_SPEC`, `chore/docs-index-sweep`). `cleanupSweepBase` best-effort deletes the remote sweep branch and local worktree after every run.
- `runPerIssueScenarioSweepTick(cycleCount, sweep = boundPerIssueSweep())` (`trigger_cron.ts`): the cron dispatch seam. Off-cadence cycles (`cycleCount % PER_ISSUE_SCENARIO_SWEEP_INTERVAL_CYCLES !== 0`) no-op. On-cadence with a non-null bound thunk it awaits the sweep inside a try/catch that logs and swallows any throw. When `cronBoundary` is `null` (e.g. the module was imported rather than launched as the cron entry script) `boundPerIssueSweep()` resolves to `null` and the tick **skips the pass with a warning log** — it never falls back to a cwd-derived identity. Called unconditionally every tick from `checkAndTrigger`.
- `runJanitorPass(deps, targetReposDir)` / `discoverTargetRepoWorktrees(deps, targetReposDir)` (`devServerJanitor.ts`): walks `{targetReposDir}/{owner}/{repo}/` (default `TARGET_REPOS_DIR`, which may be a general projects folder shared with non-ADW repos, not an ADW-only directory) and kills stale dev-server processes left behind in terminal-stage or old worktrees. A `{owner}/{repo}` directory is admitted as an ADW target repo only when it carries **both** a `.git` entry and the `.adw` marker directory written by `adw_init` — an unmarked repo is skipped entirely before any `GitContext` construction, token resolution, or `lsof` probing, and the skip is silent (not logged) since it is the expected, common case on a shared projects folder. The per-repo worktree listing (`deps.listWorktrees`, extracted into `discoverRepoWorktrees`) is wrapped in its own try/catch: a failure (GitHub App not installed, deleted repo, network error) logs `Janitor: skipping ${owner}/${repo} — worktree listing failed: …` at `warn` and skips just that repo, so the rest of the pass still runs (#812).

## Contracts & Invariants

- `parseDependencies` only returns issue numbers from the heading section; `parseKeywordProximityDependencies` is a superset.
- The in-memory dependency cache is keyed by `issueNumber:sha1(body)[:12]`; a body change invalidates the cache entry.
- `findOpenDependencies` is fail-closed: any error fetching a dependency's state causes that dependency to be treated as OPEN and block the issue.
- Pure / no I/O in `regionOverlap.ts`: it imports no side-effecting modules. All GitHub writes (issue body update, comment) live exclusively in `regionOverlapSignals.ts`.
- Deadlock-free overlap tie-break: within a cluster of mutually-overlapping issues, the lowest issue number (or the lowest in-flight member, if any are in-flight) is always the anchor that others defer behind — no two issues can each block the other.
- No false positives: a candidate with no path signal (no `## Relevant Files` or `## Touched Files` section) is never serialized.
- `registerRegionOverlapBlocker` is idempotent: it checks for the `<!-- adw:region-overlap -->` annotation before writing, so a second call for the same deferral is a no-op (no duplicate `## Blocked by` line, no duplicate comment). A write failure is caught and logged rather than thrown — the in-memory deferral already excluded the issue for the current cycle, and the next cycle retries.
- `checkIssueEligibility` returns `open_dependencies` before `concurrency_limit` — dependency checks gate concurrency checks, not the other way around.
- `decideIssueOpenedRoute` precedence: `opt_out` > `conflict` > `classified` > `infer`. Opt-out is unconditional.
- When `route.kind === 'conflict'`, `routeIssueOpened` posts a `MULTI_LABEL_REFUSAL_COMMENT` and returns `refused_multi_label` — no spawn occurs.
- When `route.kind === 'infer'`, `classifyAndSpawn` is called with `persistInferredLabel: true` so the LLM-inferred classification label is written back to the issue for cron label-recovery.
- `mergeWithConflictResolution` no longer classifies forge error text (`isMergeConflictError` is gone); the local merge check is the source of truth. It runs the scenarios again on every branch it brought base commits into and never asks the forge to merge a red or untested combination. It stops early only when retries of a clean-checking branch are exhausted (`stale_retries_exhausted`) or the outer attempts run out; an `unavailable` check (failed fetch) is no evidence of conflicts and is retried like `clean`.
- `handleCancelDirective` is synchronous (uses a spin-wait for SIGKILL timing) and returns `true` even when individual steps fail — all errors are logged and execution continues to subsequent steps.
- `resolveResumeSpawn` is pure and total: no I/O, no side effects; always returns a valid descriptor. It defaults to `'adws/adwSdlc.tsx'` when `orchestratorScript` is absent on the state — back-compat for every adwId created before PR-review began persisting `orchestratorScript` (see `app_docs/feature-9gjajh-pr-and-merge-phases.md`), and for SDLC adwIds, which persist that same script at their own init.
- Takeover routing correctness: `trigger_cron.ts`'s takeover branch reads the takeover adwId's top-level state and routes via `resolveResumeSpawn`; if that state is unexpectedly absent, it falls back to spawning SDLC directly rather than crashing.
- `resolveResumeSpawn`'s args are always `[String(issueNumber), adwId]`, passed before any target-repo flags at the spawn call site, to avoid positional collision.
- `isScenarioStale` is pure and age-only, and it is the only removal gate: no tag on the feature file exempts it.
- A feature file whose merge date can't be resolved (`getMergedAt` returns `null` or throws) is skipped, not deleted, and self-heals on the sweep's next cycle.
- The sweep never lists a feature or step file under the configured regression directory, and never deletes a step file a surviving feature file still uses (with a usage report) or a step file outside the per-issue directory (without one) — so a shared `## Step Def Directory` can never lose a definition the Regression Suite needs, which the static-check gate could not catch (cucumber loads step files by glob; nothing imports them).
- One dry run per sweep answers both questions: which step files to keep, and — combined with the paths that actually landed — which definitions are unused afterwards. No second dry run, no resync after a removal that failed to land.
- An unused-steps report (cucumber-jvm, playwright-bdd) is never treated as a usage report: it keeps no step file outside the per-issue directory by usage, and the chore lists only reported definitions inside the step-definition directories, less landed files and shared patterns. A definition the reader cannot place uniquely is at `unknown`, line 0, so it never reaches the chore — nothing is guessed.
- At most one open removal chore per repository: the marker line `Reconciles: unused-step-definitions` is the idempotency signal; a failed open-issue listing files nothing. No issue is filed when nothing is unused, when the framework is not supported, or when the report is unavailable. The sweep itself never deletes a step definition by usage — the chore hands that to the pipeline, which can trace dead helpers and imports.
- The step-usage path never throws into the sweep: dry-run, parse, listing and filing failures are logged and the feature-file removal still proceeds.
- The sweep never commits a removal to the cron host's own base checkout (`frameworkRepoRoot` is never `reset --hard`) and never pushes the default branch directly — both the lease-rejected-push and stranded-local-commit failure modes are structurally ruled out.
- Because the removal is committed only on the dedicated `chore/scenario-sweep` branch — never to the local base — a push/PR/merge failure never removes the files from the index `defaultListFeatures` re-lists from; the still-open PR (found by `findOpenSweepPr`) is the retry/idempotency signal across sweep cycles, not a re-committed local state.
- `persistRemovalViaPr` never throws: a push/PR/merge failure is logged at `error` (not swallowed at `warn`) and the function returns, leaving the PR open (if one was opened) for the next cycle or a human/CI to merge.
- The sweep worktree/branch is best-effort pre-cleaned at the start of `prepareSweepBase` (via `ctx.removeWorktree`) and torn down via `cleanupSweepBase` in a `finally` on every exit path of `runPerIssueScenarioSweep`, so a stale worktree from an interrupted prior cycle never blocks the next one.
- `boundary` is a **required, not optional** field on `PerIssueSweepDeps` — a cwd-derived default would silently resweep whatever repo the cron process happens to be checked out in (the framework repo, since `assertCwdIsRepoRoot()` pins cron cwd there) instead of the target repo the cron was launched against. `runPerIssueScenarioSweepTick` enforces skip-not-fallback: a `null` launch boundary skips the pass rather than supplying one.
- A `{owner}/{repo}` directory under `TARGET_REPOS_DIR` is an ADW target repo for the janitor only when it carries both `.git` and `.adw`; a failure listing one repo's worktrees never aborts the pass (#812).

## Configuration

`MAX_AUTO_MERGE_ATTEMPTS` is a core constant. The LLM fallback in `extractDependencies` calls `runDependencyExtractionAgent` which uses the standard agent infrastructure (logs dir, state path). `DEPENDENCY_KEYWORDS` is a module-level constant array. The `routeIssueOpened` DI deps default to production implementations via `buildDefaultIssueOpenedRouterDeps`. Region-overlap detection is driven entirely by `## Touched Files` or `## Relevant Files` sections in issue bodies (bullet lists or inline backtick paths) — there is no separate config flag to enable or disable it. `resolveResumeSpawn` has no configuration of its own — it reads `state.orchestratorScript` (persisted by each orchestrator at init/completion) and falls back to `'adws/adwSdlc.tsx'` when absent. `RETENTION_DAYS = 14` gates the per-issue scenario sweep. The sweep reads, from the target's `.adw/scenarios.md` in its sweep worktree, `## Per-Issue Scenario Directory`, `## Regression Scenario Directory`, `## Step Def Directory` and `## BDD Framework` (`cucumber-js`, `cucumber-jvm` and `playwright-bdd` have readers), and from `.adw/commands.md` `## Install Dependencies` and `## Run Scenarios by Tag` (whose `{tag}` filter becomes the dry run). The removal chore lists at most 100 definitions per issue. `SWEEP_BRANCH = 'chore/scenario-sweep'` (`perIssueSweepPersist.ts`) is the stable dedicated branch the sweep removal is pushed to and PR'd from; `SWEEP_COMMIT_MESSAGE = 'chore: sweep stale per-issue scenarios (>14d post-merge)'` is unchanged from the pre-#758 direct-commit message.

## Gotchas

- The LLM fallback in `extractDependencies` is triggered only when `totalRefs > 0 && proximityDeps.length < totalRefs` — it is not called when the body has no `#N` references at all, or when the proximity parser found as many as there are total references.
- `syncWorktreeToOriginHead` in `mergeWithConflictResolution` pulls `origin/<headBranch>` into the worktree before the conflict check so the local and remote views are in sync; failures are logged as warnings and the loop proceeds.
- `checkLocalMerge` does a real `git merge --no-commit --no-ff` of `origin/<base>` and aborts in a `finally`; if the abort itself fails (already clean), the exception is swallowed.
- `handleCancelDirective` uses a synchronous spin-wait (busy loop for 500 ms) between SIGTERM and SIGKILL — this is intentional because cancel is a rare manual operation and the context does not support async waits.
- `resolveConflictsViaAgent` (now in `baseIntegration.ts`) starts the actual merge (with conflict markers) before invoking the agent; if the merge happens to succeed cleanly (no conflict), the function returns true immediately without calling the agent.
- The `MULTI_LABEL_REFUSAL_COMMENT` references the CRON recovery layer as the mechanism that picks up the issue after label cleanup — this relies on `evaluateLabelRecovery` in the cron filter.
- The region-overlap pass only runs over issues already deemed spawn-eligible in the current cron cycle — an issue that is `paused`, `awaiting_merge`, or already `active` only contributes its `inFlight` signal when it appears in that same cycle's eligible set.
- The inserted region-overlap annotation line is `#N <!-- adw:region-overlap -->`, placed immediately after the first `## Blocked by` / `## Dependencies` / `## Depends on` heading (a new `## Blocked by` section is appended if none exists). Placement matters because `parseDependencies` is first-heading-wins.
- No LLM fallback for region-overlap: detection only uses the deterministic `## Relevant Files`/`## Touched Files` body-section parse. An issue with neither section is never serialized — safe (no false positives) but a possible missed detection.
- `resolveResumeSpawn`'s SDLC default means a `review_failed` state that predates `orchestratorScript` being persisted resumes as SDLC even if it was actually a PR-review run — the risk is bounded, since `orchestratorScript` has been stamped by both orchestrators since this resolver shipped.
- `## Retry` on a `post_merge_bdd_red` park re-arms to `phase_timeout` like any `human_gated` park (`retryHandler.ts` logs the recorded park reason); `## Continue` waives nothing for it. The resumed run skips plan, build and PR creation through its comment-derived recovery point (`pr_created`; the park comment is not a stage header), re-runs the scenario fix loop and review, and ends at `awaiting_merge`. `executePRPhase` pushes its safety-net commit when PR creation is skipped, so `adwMerge`'s reset to `origin/<head>` cannot discard it.
- The dry run's report `uri`s are relative to cucumber's working directory. A `## Run Scenarios by Tag` command that changes directory first yields paths the worktree does not hold, and the report is rejected as `unavailable` rather than trusted.
- Cucumber counts a step that matches two definitions toward neither, so a definition whose pattern is shared with another can show no use. Both queries treat shared-pattern definitions as used: never listed as unused, and their files never removed.
- A `## Run Scenarios by Tag` command with no `{tag}` filter the reader recognises (`--tags`/`-t` for cucumber-js, `-Dcucumber.filter.tags=` for cucumber-jvm, ADW's own Playwright command for playwright-bdd) cannot be turned into a dry run; the report is `unavailable` and only per-issue-directory step files are removed by name.
- An unused-steps report describes the default branch before this cycle's removal, so definitions that only this batch leaves unused are listed by the next sweep, once the removal has merged.
- cucumber-jvm names an annotated definition by its Java method, not by file and line; a duplicate class in the same package, an overloaded method, or a lambda-style definition (`(Steps.kt:12)`) cannot be located and is dropped from the chore. The `mobile:kotlincm` `## Scenario Run Contract` (`.claude/commands/adw_init.md`) requires the `:scenarios` test task to pass every `cucumber.*` system property on to cucumber-jvm, which is what makes the dry-run properties reach it.
- playwright-bdd prints locations relative to `features/` (the install command's `cd`); the reader rebases them onto `ADW_PLAYWRIGHT_PROJECT_DIR`. A `web` repository with a custom run-by-tag command gets no dry run.
- The reader tests run against captured real output (cucumber-jvm 8.0.4 `unused` plugin, playwright-bdd 9.2.1 `bddgen export --unused-steps`) in `adws/core/__tests__/fixtures/cucumberJvmUnused/` and `playwrightBddUnused/`; the capture commands are in the test headers.
- `perIssueScenarioSweep.ts` and `perIssueSweepStepUsage.ts` import `loadProjectConfig` and the check runner from their own modules, not the `../core` barrel, because `perIssueScenarioSweep.test.ts` mocks the barrel down to `{ log }`.
- `adws/triggers/__tests__/fixtures/perIssueScenarioSweep.base.ts` is a frozen copy of the pre-change sweep used by the behavioural equivalence test; do not "fix" it alongside the live sweep.
- `DEFAULT_DEPS.listWorktrees` (`devServerJanitor.ts`) constructs a `GitContext`, whose constructor probes the token provider; with the GitHub App configured that throws `HTTP 404` for any repo the App is not installed on — by design (#791/#792). Isolate it in the caller; never soften the resolver.
